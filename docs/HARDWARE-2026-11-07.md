# Hardware validation — 2026-11-07

The independent Rust implementation was exercised against a powered GSK CNC on a private LAN with the owner's authorization. The owner's allowed test range was **O3000–O4000**. The controller's exact model and firmware were not established.

The public report contains only test program names and hashes. Local IPs, workstation paths, production directory listings and raw operational logs are not published.

## Windows x64

Before writing, `list` and `stat` confirmed that **O3996.CNC and O3997.CNC did not exist**; stat returned `0x8016`. Initial uploads also used `--no-clobber`.

| Test | Bytes | Result |
|---|---:|---|
| O3996 initial upload + read-back verification | 80 | SHA-256 matched |
| O3996 independent receive in another process | 80 | Exact local byte comparison passed |
| O3997 upload + read-back verification | 132,557 | SHA-256 matched |
| O3997 independent receive in another process | 132,557 | Exact local byte comparison passed |
| Attempt to overwrite O3996 with `--no-clobber` | — | Refused with exit 2; subsequent verification confirmed unchanged contents |
| Replace own O3996 fixture with a shorter file | 40 | Exactly 40 bytes returned, no old trailing data |
| O3996 shorter version, independent receive | 40 | Exact byte comparison passed |
| Full directory enumeration | multiple pages | Successful end page and directory close |

Rust also independently verified O3998 and O3999 created by the earlier C# implementation. Their SHA-256 hashes matched the original local fixtures, establishing interoperability with files transferred through MiniSock.dll. These two programs were not modified by the Rust tests.

## Linux x64 / WSL

The same Rust source was cross-compiled to `x86_64-unknown-linux-musl` using rust-lld, then run as a **Linux ELF executable** in Ubuntu 24.04 under WSL. This was not the Windows executable launched through WSL interop.

- Read O3997 from the real controller and compared SHA-256 with the 132,557-byte source.
- Verified the current short O3996 fixture before writing, uploaded those same 40 bytes, verified by read-back, and received it into a separate local file.
- Ran all 17 loopback integration scenarios, including SIGINT cleanup.

The static Linux executable was identified by `file` as ELF 64-bit x86-64, static PIE, stripped. The Windows PE imports only Windows system libraries; it does not import MiniSock.dll or a separate Visual C++ runtime DLL.

## Scope of the evidence

The local fault-injection fixture covers lost replies, retries, bad offsets, stale packets, truncated reads, early EOF, controller errors, verification mismatches and preservation of existing local files. Those failure conditions were simulated on loopback, not introduced into the live controller network.

Hardware tests confirm this controller and these file sizes. They do not establish compatibility with every GSK firmware, arbitrary maximum file sizes, parallel clients, remote atomic writes or program execution. The repeatable hardware harness deliberately refuses to run against already existing O3996/O3997 names.
